# AirSIM Apps v0.9.7 (80)

This release publishes the Android AVF Bridge, Android Standalone, and iPhone/Watch apps from the `VoBLE` branch. The independent Linux AVF Agent remains `v0.4.6`. This release does not update the Debian package and does not change the release workflow.

## Release assets

- `AirSIM-Android-AVF-0.9.7.apk`: the Android Bridge for the older AVF architecture, package name `com.airsim.phonecontrol`.
- `AirSIM-Android-Standalone-0.9.7.apk`: the recommended single APK with a built-in Agent, package name `com.airsim.phonecontrol.standalone`.
- `AirSIM-iOS-0.9.7-unsigned.ipa`: arm64 main app, Watch App, and Live Activity Extension, for the user to re-sign.
- `SHA256SUMS.txt`: SHA-256 checksum list for the three artifacts above.

Both APKs use the existing official release certificate, version `0.9.7` / `80`, and are not debuggable. Different package names cannot overwrite each other. The public unsigned IPA contains no Apple signature or provisioning profile and cannot be installed directly or submitted to TestFlight. The maintainer uploads TestFlight separately with their own production app identifier, production APNs, and Xcode automatic signing. A successful upload does not mean processing is finished or that review has passed.

## Main changes

- VoBLE is an independent Bluetooth mode in Settings. It does not depend on Wi-Fi, Relay, or PushKit. Authenticated BLE GATT carries control and AES-256-GCM-encrypted G.711 μ-law 8 kHz mono call audio. It does not provide Bluetooth PAN network sharing.
- Automatic mode chooses VoWLAN → VoBLE → cloud according to the actual dial route. Bluetooth availability no longer depends on VoWLAN pairing or HTTP 200. The dialer, Agent list, and Live Activity show Bluetooth status.
- Fixes races among provisional and authoritative call IDs, generation, late status, and duplicate hang-up. An authenticated hang-up of the same terminal state can complete idempotently and will not act on the next call by mistake. Dynamic Island Bluetooth actions are performed by the main app's authenticated session.
- Adjusts bounded buffering, playback frame fill, and cellular uplink routing for Bluetooth audio. After unpairing, both sides' credentials are cleared and scanning resumes. Connection timeout waits for the old GATT to disconnect and does not create an overlapping connection.
- Android adds a VoBLE authentication settings page, default-call SIM/eSIM selection, and a Shizuku check at startup. When Shizuku is missing, it offers the official download address. When Shizuku is not running or not authorized, it offers the matching entry.
- Android crash reports enter the system share sheet only when the user chooses to send them. Size is limited and content is redacted. They are not uploaded automatically.
- iPhone can manually bind an Agent, delete a paired device, and delete recent calls. Device history does not cache phone numbers. The new APK's BLE, VoWLAN, and Standalone heartbeats read the current call-SIM information and do not reuse an old number when the number cannot be read.
- Adds a separate signature-verification note for dynamic libraries embedded in diagnostic Debug packages, so a missing signature does not cause a pre-launch DYLD crash. Official releases use a Release build and do not reuse the diagnostic package.

## Verification and known limits

Before release, iOS 92 XCTest cases, the shared Android Bridge/Standalone tests, 47 PCM bridge checks, 46 Relay tests and the syntax check, and the Go Agent/installer tests were run again. Official artifacts were checked separately for version, the Android certificate, the non-debuggable attribute, and Apple nested-target signatures.

iPhone Air and Samsung Flip7 have already carried real BLE calls. The user confirmed that audio reached the iPhone and that later calls were normal. Logs contain evidence of bidirectional media and end-of-call cleanup. The device list opens normally on device. Full round-by-round evidence is in the [physical-device test matrix](../voble-real-device-test-matrix.md). Historical failure scenarios or unit tests must not be treated as full-hardware acceptance for this release.

- BLE-only hang-up races have regression tests on both ends. Final on-device retesting, re-pairing after a real SIM swap or deletion, dual-SIM carrier routing, multi-vendor audio, and 30-minute stability still need acceptance.
- Apple Watch does not connect to Android BLE directly. Mirrored incoming calls and audio are managed by the iPhone/watchOS system. Combined Watch on-device acceptance is not finished.
- After the user force-quits iOS, BLE background wake is not guaranteed. Once a call starts, the transport is locked and does not drift among the three paths without a prompt.
- Cloud number heartbeats from the older Linux AVF Agent still read registration metadata and have not yet moved to the current SIM query.
- A diagnostic device previously showed ActivityKit `SessionCore.PermissionsError Code=3`. The launch-crash fix is not presented as having solved every Live Activity permission problem.
