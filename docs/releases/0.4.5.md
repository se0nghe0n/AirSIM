# AirSIM AVF Agent 0.4.5-1

This release fixes HTTP 403 when the Android host reaches the Agent over a dynamic AVF private network, which caused iPhone pairing to fail. The Agent can now use a trusted local socket address to recognize an Android–AVF same-subnet connection. Public networks and unrelated LANs are still rejected. The error text changes from “USB local-network access only” to “AVF private-network access only.”

## One-time signing-key migration

The old v0.4.4 release private key was not retained, so the existing `airsim-installerd` does not trust the new signature. **A device that has `0.4.4-1` installed cannot tap “Update to the latest version” directly in the Android app.** First run this in the original AVF Linux Terminal:

```sh
curl -fsSL --connect-timeout 10 --max-time 90 --retry 2 --proto =https --proto-redir =https --tlsv1.2 -o /tmp/airsim-rotate-v0.4.5.sh https://github.com/kai-wu-cortex/AirSIM/releases/download/v0.4.5/rotate-avf-key.sh
printf '%s  %s\n' '9ae6b8c69d5d9877638a50240282a67d06b73d807dba444c816c5efb9c5ec04d' /tmp/airsim-rotate-v0.4.5.sh | sha256sum -c - && sudo sh /tmp/airsim-rotate-v0.4.5.sh
```

The script accepts only an AVF that already has `0.4.4-1` installed and whose retained package matches the v0.4.4 Release exactly. If any pre-check of download, signature, package name, architecture, or Debian dependencies fails, it does not install. It keeps the old package as `previous.deb` and, after the update, verifies the AirSIM Agent and installer. On failure it tries to roll back. It does not change DJOneHub's `7575` service, the AirSIM control token, Push configuration, or AVF data. The old private key is lost, so this script cannot be cross-signed with the old key. Check the GitHub domain, the script digest below, and the new public-key fingerprint.

- New release public key (Ed25519 raw 32 bytes, Base64): `QQPJXjO2mcx13qhv74lXen8ytjJZ2hMCz+ERlz6w5qg=`
- New release public key DER SHA-256: `4c39d5afdca2dddd8d22c0a5e02da18e7f07db789baac04bce4cfcd57491b3f4`
- Migration script SHA-256: `9ae6b8c69d5d9877638a50240282a67d06b73d807dba444c816c5efb9c5ec04d`
- Debian package SHA-256: `037d5c4e37898420f8ffaebae18519d4cf25910e5c81c3e4d4a7f87364cf6648`

A first install on an AVF that has no older AirSIM Agent uses `install-avf.sh` from the same Release, **not** `rotate-avf-key.sh`. After migration, later updates signed with the new key can be used from the app's install-management page.

## Acceptance

1. `dpkg-query -W airsim-avf-agent` shows `0.4.5-1`, and both `airsim-agent` and `airsim-installerd` are running.
2. The Samsung phone reaches `8575/api/health` over the current dynamic AVF private network and gets HTTP 200, with `product=airsim` and `version=0.4.5`. `8576` still requires the control token.
3. Pair the iPhone and Samsung phone again, confirm HTTP 403 is gone, then verify Relay, phone, and PCM separately. A successful health check is not full acceptance of the call path.

Full troubleshooting and rollback notes are in the [AVF installation guide](../AVF_INSTALL_GUIDE.md).
