## Main changes

- Preferred ports for Samsung VoWLAN control and PCM listeners change to `7592/7593`, avoiding DJOneHub's `7590/7591`. If the preferred ports are taken, the service binds a system-assigned port only on the selected hotspot address and publishes the actual control/PCM ports through Bonjour, so a `BindException` does not leave the service stuck in preparing.
- The Android status page states the current VoWLAN / cloud / offline mode clearly, so diagnostic paths are easier to tell apart.
- The iOS Settings page shows transport mode and status, and provides a four-stage cloud-mode self-check: local Push credentials, Relay identity, device registration, and Agent heartbeat. The self-check does not dial or send SMS.
- Cloud-call PCM adds a bounded receive buffer, frame fill after playback completes, and a single send queue on a 20-millisecond cadence, reducing stall risk from network bursts and continuous sending. It stays compatible with the existing Relay PCM protocol.

## Android update

1. Download `AirSIM-Android-0.9.1.apk` and check the SHA-256 against the release-certificate fingerprint above.
2. A device that already has the officially signed v0.9.0 can update in place and keep local pairing data. If the device still has an old debug-signed package, it cannot be overwritten. Record the AVF address and pairing data first, then uninstall the old package and install the new one.
3. Start AirSIM on the Samsung phone and confirm it is still the default phone app and that Shizuku is authorized. Confirm VoWLAN status is ready and that diagnostics show the actual control/PCM ports. If DJOneHub runs on the same device, port `BindException` should no longer appear.
4. With the iPhone and Samsung phone on the same hotspot, retest dial, answer, hang-up, and two-way voice. Then switch to cloud mode, use the Settings self-check to confirm Relay, registration, and the Agent heartbeat, and check audio in a real call.

## iOS IPA re-signing

The public IPA is an unsigned build. It contains no development certificate, provisioning profile, or device UDID, and cannot be installed directly. Use your own Apple Developer Team to configure the Bundle ID, signing, and provisioning profile separately for the main app, Watch App, and Live Activity Extension, and make your Relay `ALLOWED_BUNDLE_ID` and APNs topic match the main app. Full steps are in the [iOS README](../../iOS/README.md).

## Security boundary

This project is limited to the noncommercial uses allowed by the license. The APK/IPA does not contain an APNs private key, Dashboard token, Cloudflare token, AVF control token, Android release private key, or Apple signing identity. AirSIM cannot replace the system emergency-call capability.
