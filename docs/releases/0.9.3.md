# AirSIM Apps v0.9.3

AirSIM Apps v0.9.3 adds visibility and automatic cloud takeover for multiple Android Agents. The iOS dialer now shows the Android phone currently routed to, its number, the Agent type, and VoWLAN and cloud online status. When the same iPhone is paired with multiple Standalone / AVF Agents, the full list can be opened to inspect each device.

## Main changes

- The iOS dialer adds a “Current Android” card showing the device name, phone number, Standalone/AVF type, and two independent statuses: VoWLAN and cloud.
- When the iPhone is paired with multiple Android Agents, an “All N” entry appears. The list shows the same information for each device. Offline devices can still be viewed when no current route is available.
- VoWLAN prefers a locally reachable Agent. When VoWLAN is unavailable, Relay selects the Agent with the newest heartbeat in the last 90 seconds as the current cloud route.
- Relay stores multiple heartbeats by the stable `android_agent_id`, and keeps the older single-Agent mirror and the `legacy` compatibility entry.
- Android Standalone derives an irreversible stable identifier from the package name and `ANDROID_ID`, and reports the device name, manufacturer, model, and optional SIM number.
- AVF Agent v0.4.6 reads the same metadata from authenticated Android pairing information and includes it in the cloud heartbeat.
- The phone number is not placed in the Bonjour advertisement. VoWLAN returns it only from the health interface after HMAC authentication. The cloud reads it only through the authenticated device-status interface. When the carrier has not written a number, or the user denies permission, the UI shows “Number not provided.”

## Android update

1. Download `AirSIM-Android-Standalone-0.9.3.apk` and check the SHA-256 on this page and the release-certificate SHA-256.
2. Overwrite Standalone with `adb install -r` or the system installer. The package name remains `com.airsim.phonecontrol.standalone` and does not overwrite the older AVF app.
3. Grant the optional “Read phone state/number” permission if the SIM number should appear on the iPhone. Denying it does not affect dialing, VoWLAN, or cloud mode.
4. Open the app, confirm that Relay heartbeats resume, then check the device name, number, and current route on the iPhone dialer.

## iOS IPA re-signing

The public IPA is an unsigned build. It contains no development certificate, provisioning profile, or device UDID, and cannot be installed directly. Use your own Apple Developer Team to configure the Bundle ID, signing, and provisioning profile separately for the main app, Watch App, and Live Activity Extension, and make your Relay `ALLOWED_BUNDLE_ID` and APNs topic match the main app. Full steps are in the [iOS README](../../iOS/README.md).

- 40 Relay tests, 23 iOS simulator tests, Android Standalone/Core/Bridge tests, Go Agent/Installer tests, and Debian packaging tests all passed.
- The official Android APK is `0.9.3 (76)`, `minSdk 29`, `targetSdk 35`, `debuggable=false`. The release signature matches the previous two releases, and `apksigner verify` passed.
- The iOS Release `iphoneos` build passed. The main app, Watch App, and Live Activity Extension are all `0.9.3 (76)`. The public IPA contains no `_CodeSignature` or `embedded.mobileprovision`.
- Multi-Agent Relay storage, active-route selection, old-response compatibility, and iOS decoding have automated coverage. Xiaomi/Samsung cross-network automatic switching still needs end-to-end retesting with the official package.

## Security boundary

This project is limited to the noncommercial uses allowed by the license. The APK/IPA does not contain an APNs private key, Dashboard token, Cloudflare token, AVF control token, Android release private key, or Apple signing identity. AirSIM cannot replace the system emergency-call capability.
