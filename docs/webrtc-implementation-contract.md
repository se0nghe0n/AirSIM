# WebRTC implementation contract (signaling v1, privileged IPC v2)

The cloud call identity, CallKit lifecycle, durable commands, pairing, and SMS remain unchanged. VoWLAN keeps HMAC control on hotspot port 7592 and carries `webrtc_offer` / `webrtc_answer` there. Those peers use host ICE only. Telephony samples remain inside the privileged native-peer process; no raw-audio listener or IPC is used. Port 7593 is not a PCM listener. `media_transport: webrtc` means native audio-only WebRTC/Opus. iPhone cloud calls succeed only for `webrtc`; `legacy_pcm` is not an iPhone carrier and a failed negotiation does not open a PCM engine. iPhone offers; Android answers. The authenticated call WebSocket carries control and signaling, never scheduled PCM. WebRTC audio uses ICE/DTLS-SRTP, directly or via configured TURN.

## Signaling

Each JSON signaling message has `action` (`webrtc_offer`, `webrtc_answer`, or `webrtc_ice`), `call_uuid`, numeric `generation`, and random UUID `session_id` chosen by the iPhone per negotiation. Offer/answer carry `sdp`. ICE carries `candidate` object with `candidate`, optional `sdp_mid`, and integer `sdp_mline_index`. iPhone initiates only after its owner handshake is acknowledged (`answer_ok`, or `media_prepared` for an outgoing call), media transport is WebRTC, and audio startup is permitted. Outgoing calls may prepare the native peer during dialing/ringback without invoking Telecom answer. Privileged IPC `start` accepts `defer_carrier_audio: true`; an owner-checked `activate_audio` attaches the carrier device to that peer when Telecom reports active. Incoming calls start after successful answer confirmation. Android accepts a new offer session, queues at most 128 remote ICE candidates until the remote SDP is installed, and rejects mismatched session IDs. iPhone queues remote ICE similarly. Old callbacks are fenced by owning call connection and negotiation identity. Reconnect creates a new negotiation session; hangup closes peer and carrier-device resources.

Relay validates identity, role/direction, bounded SDP/candidates, and active owner. Only an owner iPhone may send offers; only agent answers. ICE may flow both directions after a valid offer. No SDP is persisted/logged. A missing peer requires the client to renegotiate after peer_connected, rather than retaining offers indefinitely. Existing durable answer/end semantics must remain intact. `webrtc_ready` carries the current `session_id` and is sent only when both the Android native peer and verified carrier capture/uplink route are ready. iPhone reports connected audio only after this matching status and its own native connection readiness. `webrtc_failed` reports a generic error; no SDP or credentials in logs. A late Watch connection must not restart an active iPhone negotiation.

## ICE configuration

Authenticated `GET /v1/calls/:uuid/ice?role=iphone|agent` with `Authorization: Bearer <call_secret>` returns `{ice_servers:[{urls:[...], username?, credential?}], ttl:3600}` and `Cache-Control:no-store`. Authentication and expiry match the call-connect path. Server supports standard TURN REST credentials from `TURN_URLS` (JSON URL array), secret `TURN_SHARED_SECRET`, bounded `TURN_TTL_SECONDS` (60–86400, default3600, capped by call expiry), HMAC-SHA1 username expiry format. No long-lived TURN secret reaches clients. `STUN_URLS` may contain a JSON array of stun URLs. Missing TURN is reported explicitly; no silent claim that arbitrary NAT works. Native clients use all returned ICE servers; no hardcoded public service dependency. Relay readiness must require valid TURN configuration for normal WebRTC rollout. `TURN_PROVIDER=cloudflare` may instead use `CLOUDFLARE_TURN_KEY_ID` plus the server-only `CLOUDFLARE_TURN_API_TOKEN` to POST a bounded `ttl` to Cloudflare Realtime `/v1/turn/keys/{id}/credentials/generate-ice-servers`; provider `iceServers` are validated and normalized to the same response. Use a bounded fetch timeout and generic failure response. Tests may use host candidates/local peers.

## Validation and limits

Require both app builds, focused native media tests/loopback where feasible, complete existing Relay tests plus signaling/auth/expiry/ownership tests, and legacy regression tests. Record build, exercised-media and untested-device results separately. Native simulator/emulator results are not a substitute for carrier calls, physical Q25 routing or production TURN acceptance. The rollout stays disabled until a deployment provides its own TURN configuration and matching app builds.
